# 0007. The report server runs on the system nginx, behind one name on port 80

- Status: Accepted
- Date: 2026-11-08
- Amends: [0002](0002-report-server-allow-list.md) and [0003](0003-report-server-tailnet-access.md): the "run as the user", "no root" and "specific addresses only" rules. Their serve-root and client-network rules stay in force.
- Context: lesson links from `/teach` could not use one name on every device ([serve-artefacts](../../skills/serve-artefacts/SKILL.md))

| Y-statement | |
| :-- | :-- |
| In the context of | one URL, `http://idun/`, that opens from the Mac, from tailnet devices and from the VM |
| facing | user-level nginx instances that cannot bind port 80 and do not listen on loopback, so each network has its own address and port |
| we decided for | the Debian system nginx on port 80, installed once with sudo: one `conf.d` snippet (wildcard listen, source allow-list for loopback, Parallels and tailnet), a user-owned snippet directory for new locations, and a sudoers rule for `nginx -t` and `systemctl reload nginx` only |
| and neglected | a sysctl that lowers the unprivileged-port floor with the user instances kept; `setcap` on the nginx binary; Tailscale Serve (tailnet only, and it already holds 443 and 8443) |
| to achieve | one name and no port everywhere; new content is files in `~/.cache/agent-skills/` and new locations are files in `/etc/nginx/agent-skills.d/`, with no root after the first run |
| accepting that | a one-time root step; one nginx process for all networks; workers run as `www-data`, so served files must be world-readable; a reload is needed to add a location |
| because | the owner prefers a platform that is set up once and then extended by deploying content |
| revisit when | the VM gains a network that must not be served, or a second user needs different content |

## Rules

- The snippet MUST be generated by `report_server_system` from the same directive builders as the user-level instances, so the dot-segment, symlink and 404-for-every-refusal rules cannot drift.
- Clients MUST be limited by source address to loopback, `10.211.55.0/24`, `100.64.0.0/10` and `fd7a:115c:a1e0::/48`; every other client reads `404`. A wildcard listen is allowed only with this allow-list.
- The sudoers rule MUST allow exactly `/usr/sbin/nginx -t` and `/usr/bin/systemctl reload nginx` for the owner, with no wildcards.
- The stock `default` site MUST be disabled, because it also claims port 80 as `default_server`.
- The user-level package `report_server` and its architecture tests stay unchanged and remain the fallback that needs no root.

## Consequences

- The snippet directory is owned by the user and included by a root-run nginx, so the owner can make nginx serve any file that `www-data` can read. This is not root access; it widens what a compromised user session can publish.
- If `www-data` cannot read a file, the client sees `404`. Tools that write served files MUST NOT create them mode 600.
- Tailscale being down no longer affects binding: the wildcard listen does not depend on the tailnet address.
- Installation is `skills/understand/server/install-system.sh` (supports `--dry-run` and `--uninstall`); the user units can be disabled after it succeeds.
